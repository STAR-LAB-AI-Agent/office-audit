# 本地性能与摘要压缩基线

## 实验条件

- 日期：2026-09-02
- 运行时：课程绑定 Python 3.12.13
- 输入：脚本在临时目录生成的可控 `.docx`，正文段落数分别为 50、200、800；测试文件不保留到仓库。
- 重复次数：每种规模 3 次。
- 命令：

  ```powershell
  python scripts/benchmark_audit.py --sizes 50,200,800 --repeats 3
  ```

`p95_approx_elapsed_ms` 在当前脚本中取 3 次运行的最大值，只是小样本上界，不是真正统计意义上的 P95。`summary_char_ratio` 是规则证据、问题说明和建议的字符数与输入字符数之比，只是本地摘要压缩代理，不是模型 token 计数。

## 实测结果

| 正文段落数 | 输入字符数 | 中位耗时（ms） | 3 次最大耗时（ms） | 摘要字符数 | 摘要比例 | 模型调用数 | 问题数 | 错误数 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 50 | 2,187 | 116.78 | 133.50 | 135 | 6.17% | 0 | 2 | 0 |
| 200 | 8,737 | 400.44 | 439.73 | 135 | 1.55% | 0 | 2 | 0 |
| 800 | 35,137 | 2,108.77 | 2,226.40 | 135 | 0.38% | 0 | 2 | 0 |

### 独立复跑批次

为检查基线是否受本机负载影响，于 2026-09-02T05:15:44Z 使用同一命令再次运行。输入规模、摘要字符数、模型调用数和问题数保持一致，但墙钟耗时明显波动，因此耗时只能作为本机参考：

| 正文段落数 | 输入字符数 | 中位耗时（ms） | 3 次最大耗时（ms） | 摘要字符数 | 摘要比例 | 模型调用数 | 问题数 | 错误数 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 50 | 2,187 | 279.85 | 285.01 | 135 | 6.17% | 0 | 2 | 0 |
| 200 | 8,737 | 1,067.90 | 1,128.91 | 135 | 1.55% | 0 | 2 | 0 |
| 800 | 35,137 | 6,015.23 | 6,414.52 | 135 | 0.38% | 0 | 2 | 0 |

两批次的摘要比例和 `model_calls=0` 保持稳定，耗时则受运行时负载、文件扫描和进程启动状态影响；本项目不把上述数值宣称为跨机器性能保证。

## 解释与限制

当前 CLI 先由 `python-docx` 完成本地解析、计数和规则筛选，再保留有限的结构化证据；因此在本实验中没有模型调用，`model_calls=0` 是实现事实。随着输入规模增加，受控样例只产生两个问题，摘要字符数保持 135，比例随输入增长而下降，这支持“先结构化、后解释”的低上下文设计方向。

该实验不是与某个模型、全量正文提示词或另一种解析器的 A/B 对照，也没有证明所有真实文档都会保持固定摘要大小。后续应使用许可明确的真实公开文档、更多缺陷密度和多轮重复实验补充对照，并把模型接入后的真实 token、延迟和质量指标单独记录。
