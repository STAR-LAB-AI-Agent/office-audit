# AI Office 文档审计实验报告

专业实习课题 #03　验证日期 2026年9月15日

## 一 实验目标与实现范围

本项目实现一个面向通用 Word 文档的只读审计 Skill。宿主负责理解请求和调用工具，Python 内核负责解析 DOCX、执行规则并输出 JSON、Markdown 或终端摘要。实验关注三个问题：规则是否按预定条件命中，报告是否能定位问题，运行是否保持输入文件不变。

检查范围包括正文、表格、嵌套表格和实际使用的页眉页脚。标题层级依赖 Heading 样式；缺章检查依赖用户提供的章节清单。空白、占位符和格式差异作为质量线索，不自动解释为确定错误。图片、文本框、OLE、SmartArt、批注、修订和公式等未审计内容单独记录。项目没有实现 OCR、专门的 PII 检测或文档自动修复。

## 二 环境与样例

9月15日在本机分别使用 Python 3.9.0 与随工作区提供的 Python 3.12.14 运行单元测试，依赖为 python-docx 1.2.0。GitHub Actions 已配置 Python 3.10、3.11、3.12 矩阵，最新 main 分支自动化工作流实际执行全部通过（参见 [GitHub Actions 动态状态](https://github.com/STAR-LAB-AI-Agent/office-audit/actions/workflows/audit-ci.yml?query=branch%3Amain)）。

测试数据分为15组合成样例与12份仓库外真实文档。合成样例在临时目录生成，运行结束后清理；真实文档用于检查解析退化和报告可用性，不随代码公开。数据集元数据许可不代表每份文件都有再分发许可。评测脚本不发起网络请求，但没有提供阻断网络的操作系统沙箱。

## 三 受控评测方法

清单中的 expected_findings 声明应出现的规则及级别，expected_absent_rules 声明不应出现的规则。warning/error 进入缺陷指标；info、未审计对象和运行错误另行检查。

计数单位是“文档与规则的组合是否命中”。同一文档中某规则出现多次，在该指标里仍只计一次，因此它不能衡量每个位置是否完整检出。TP是预期且实际出现的缺陷规则，FP是非预期出现的缺陷规则，FN是预期但未出现的缺陷规则。TN只统计清单明确声明的负例，不是全部可能规则的真负例总数。

精确率用 TP 除以 TP 与 FP 之和；召回率用 TP 除以 TP 与 FN 之和。分母为零时输出“不适用”，不伪造满分。标签必须先确定，不能为迎合实现而随意调整。规则语义有意变化时，需要说明原因并同步行为测试。

## 六 安全与配置检查

资源预检默认限制文件50 MiB、ZIP条目1000个、声明解压总量150 MiB；声明解压量超过5 MiB时，再检查总解压量与文件体积之比是否超过100。它能提前拒绝部分高风险输入，但不是内存或CPU的硬隔离，不证明所有拒绝服务风险已消除。

配置校验拒绝未知键、未知规则、非法级别、语法错误的正则及非有限数值。正则语法合法不代表没有灾难性回溯，因此自定义正则只应来自可信操作者。禁用规则会在结果中明确列出，防止“没检查”被误读成“没问题”。

写入路径检查包含同一路径、符号链接解析和现有硬链接身份比较。输入哈希核验是在已执行测试中获得的证据，不是对并发改写文件或操作系统所有行为的绝对保证。

## 七 性能与上下文开销

9月15日以 Python 3.9.0 运行 benchmark_audit.py，每种规模重复3次，得到以下本机数据。运行时其他进程负载会影响耗时。

| 正文段落数 | 耗时中位数 ms | 三次最大值 ms | 摘要字符比 |
| --- | --- | --- | --- |
| 50 | 215.93 | 229.14 | 6.17% |
| 200 | 836.08 | 1086.65 | 1.55% |
| 800 | 4979.67 | 5383.91 | 0.38% |

复现命令为 `python scripts/benchmark_audit.py --sizes 50,200,800 --repeats 3`。旧字段 p95_approx_elapsed_ms 实际取三次最大值，不是统计意义上可靠的P95。摘要字符比是字符量代理，不是模型token计数。本组文档缺陷数量较少，不能推断所有真实文档都能保持固定报告长度。

审计内核不调用模型，所以 model_calls 为0。宿主理解请求、规划工具调用和解释报告仍可能消耗token，不能把内核事实扩展成全流程零token。

## 八 结论与不足

项目已经形成可独立运行的审计器、通用Skill入口、可复现测试与只读边界。阶段1的分组规则减少了一些排版提示，交付审查补上了输入校验和覆盖说明的缺口。当前仍存在特殊文体误报、样式继承未完整解析、段内混合格式覆盖有限，以及复杂对象只定位不审计等限制。真实文档尚无完整逐项真值，不能给出整体准确率。

9月11日的三宿主记录证明当时版本能够被调用，不自动覆盖之后的代码变更。最终提交时应附准确的版本与验收状态，不以报告里的“正式版”字样代替验证。
