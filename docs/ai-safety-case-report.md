# AI Office 文档审计：人工智能安全案例报告（证据版草稿）

> 状态：阶段性草稿（2026-09-04）。本文件把已实现的安全控制、已运行的验证和剩余风险分开记录；未完成事项不写成已通过。

## 1. 案例概述

本案例研究一个面向通用 Word 文档的只读审计 Skill。用户提交课程报告、通知、会议纪要、制度文件、项目说明、申请材料或模板后，系统读取 .docx，检查标题结构、用户指定的必需章节、空字段、占位符和基础格式一致性，并输出 JSON/Markdown 审计结果。

文档是外部输入，不应被当作指令。第一版不执行宏、脚本、嵌入式对象或文档中的命令文字，不自动修改原文，也不联网上传文档。模型当前不是运行依赖；自然语言请求由透明关键词路由转换为 full、structure 或 fields_format。

## 2. 资产、威胁与安全目标

| 资产或边界 | 主要风险 | 安全目标 |
| --- | --- | --- |
| 用户原始 .docx | 被覆盖、修改或误删 | 只读打开，报告路径独立，覆盖输入时拒绝 |
| 文档正文和表格内容 | 内容包含提示注入或恶意命令文字 | 只当数据解析，不执行内容 |
| 宏、OLE、SmartArt、文本框、批注和修订 | 复杂对象内部内容被误信或静默遗漏 | 不执行；逐类报告未审计对象及影响 |
| 审计日志 | 正文、密钥或隐私信息泄露 | 只记录模式、统计、耗时、对象计数和错误码 |
| 规则与严重级别 | 模型随意改变结论或标准被硬编码 | 规则确定性执行；用户标准显式传入 |
| 公开样例 | 版权、再分发和 PII 风险 | 原文默认不入 Git；逐份核验前保持 pending |

## 3. 已实现的控制措施

1. 输入格式和路径校验：只接受可解析 .docx；输入不存在、格式错误和不可解析文件返回结构化 errors，不打印 traceback。
2. 输出隔离：报告和日志必须使用独立路径；输出覆盖输入文档会被拒绝；审计前后回归测试比较输入字节。
3. 不可信文档隔离：代码只读取 OOXML 结构，不调用宏、脚本或文档中的自然语言动作。
4. 不确定性显式化：图片/绘图、文本框/形状、OLE、SmartArt、批注和修订分别出现在 unsupported_objects，包含位置、数量、原因、影响和建议。
5. 标准不臆测：没有 required_sections 时只提示“未指定标准”，不把某种学校模板当作通用要求。
6. 日志最小化：JSONL 日志不记录正文、证据、自然语言请求、密码或 API key；当前 model_calls 固定为 0。
7. 数据发布闸门：manifest 只保存元数据；候选只有在文件级许可、人工 PII 抽查、下载时间、字节数和本地 SHA-256 均完成后才能提升为 verified。

## 4. 验证证据

- 10 个 unittest 回归用例通过，覆盖正常文档、空字段、标题跳级、缺章节、未知/歧义请求、不可解析文件、未审计对象、报告覆盖保护和日志脱敏。
- 受控缺陷标签验收 5/5 通过，见 fixtures/controlled-cases.json 和 docs/controlled-cases.md；运行不联网，临时变体不保留。
- 公开候选已完成仓库外全量工程评估：12/12 均能解析，audit_error=0、hash_mismatch=0、invalid=0、model_calls=0；评估器未联网，也未修改 manifest。
- 公开候选仍未完成人工 PII 抽查和逐份文件级再分发许可核对，因此所有 12 条候选仍为 pending。
- Skill 官方校验返回 Skill is valid；Python 3.12.13 与 python-docx 1.2.0 完成编译和测试。

## 5. 风险登记

| 风险 | 当前等级 | 状态 | 处理原则 |
| --- | --- | --- | --- |
| 复杂对象内部文字未参与审计 | 中 | 已显式暴露 | 逐对象人工复核，不输出“全面通过” |
| 文档含提示注入或命令文字 | 高 | 已隔离 | 内容只作为数据，未来模型接入仍不能改变工具权限 |
| 公开样例含个人信息 | 高 | 未完成 | 先预览提取文本并人工抽查，未完成则不公开原文 |
| 单文件再分发权不明确 | 高 | 未完成 | 记录 UNVERIFIED，原文不进 Git |
| 默认规则漏报行业特定要求 | 中 | 已知限制 | 使用者提供 required_sections 或自定义 rules |
| 当前没有在线模型语义判断 | 低/中 | 有意取舍 | 先保证确定性、低依赖和可复现，模型作为后续适配器 |

## 6. 残余风险与结论

当前版本适合作为离线、只读的文档质量预检工具，不应被解释为法律审查、隐私清除器、恶意文档沙箱或“文档已完全合规”的证明。尤其是未审计对象和真实公开样例的版权/PII 状态必须在交付时单独展示。

结论：第一版已经验证了最小安全边界和核心规则链路；在创建 GitHub 公开仓库前，必须完成候选样例人工复核、密钥和个人信息扫描、最终演示与报告核对，并继续保留所有未验证状态。
